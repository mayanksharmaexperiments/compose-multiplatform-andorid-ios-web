# Room Database in Kotlin Multiplatform (KMP)

This skill provides guidelines and patterns to configure local relational databases using **Room Multiplatform** across Android, iOS, and other target environments.

---

## 1. Room Declarations in `commonMain`
*Declare `@Entity` tables, `@Dao` interfaces, and abstract `@Database` classes in the shared commonMain source set.*

### 1. Room Entity:
```kotlin
package org.example.project.data.local

import androidx.room.Entity
import androidx.room.PrimaryKey

@Entity(tableName = "clients")
data class ClientEntity(
    @PrimaryKey val id: Long,
    val name: String,
    val phoneNo: String?,
    val address: String?
)
```

### 2. Room DAO:
```kotlin
package org.example.project.data.local

import androidx.room.Dao
import androidx.room.Insert
import androidx.room.OnConflictStrategy
import androidx.room.Query
import kotlinx.coroutines.flow.Flow

@Dao
interface ClientDao {
    @Query("SELECT * FROM clients")
    fun getAllClientsFlow(): Flow<List<ClientEntity>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertClients(clients: List<ClientEntity>)

    @Query("DELETE FROM clients WHERE id = :id")
    suspend fun deleteClient(id: Long)
}
```

### 3. Room Database Definition:
```kotlin
package org.example.project.data.local

import androidx.room.Database
import androidx.room.RoomDatabase

@Database(entities = [ClientEntity::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun clientDao(): ClientDao
}
```

## 2. Platform-Specific Database Builders
*Room requires platform-specific sqlite drivers and storage locations. Declare a builder hook in commonMain, and instantiate in platform code.*

### Common main abstract builder logic:
```kotlin
// commonMain
package org.example.project.data.local

import androidx.room.RoomDatabase

// Use expected platform context or pass a builder instantiation function
expect fun getDatabaseBuilder(): RoomDatabase.Builder<AppDatabase>
```

### Platform Implementations:
```kotlin
// androidMain
package org.example.project.data.local

import android.content.Context
import androidx.room.Room
import androidx.room.RoomDatabase
import java.io.File

actual fun getDatabaseBuilder(): RoomDatabase.Builder<AppDatabase> {
    val appContext = getAndroidContext() // Supplied via Koin / startup
    val dbFile = appContext.getDatabasePath("app_db.db")
    return Room.databaseBuilder<AppDatabase>(
        context = appContext,
        name = dbFile.absolutePath
    )
}
```

```kotlin
// iosMain
package org.example.project.data.local

import androidx.room.Room
import androidx.room.RoomDatabase
import platform.Foundation.NSDocumentDirectory
import platform.Foundation.NSFileManager
import platform.Foundation.UserDomainMask

actual fun getDatabaseBuilder(): RoomDatabase.Builder<AppDatabase> {
    val dbFilePath = documentDirectory() + "/app_db.db"
    return Room.databaseBuilder<AppDatabase>(
        name = dbFilePath,
        factory = { AppDatabase::class.instantiateImpl() } // Autogenerated by Room compiler
    )
}

private fun documentDirectory(): String {
    val documentDirectory = NSFileManager.defaultManager.URLForDirectory(
        directory = NSDocumentDirectory,
        inDomain = UserDomainMask,
        appropriateForURL = null,
        create = false,
        error = null
    )
    return documentDirectory?.path ?: ""
}
```

## 3. Room-Based Offline First Sync Architecture
*Use Room as the Single Source of Truth (SSOT). Repositories expose local DB flows to ViewModels and execute background remote calls (Supabase/Ktor) to sync data.*

```kotlin
package org.example.project.data.repository

import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.map
import org.example.project.data.local.ClientDao
import org.example.project.data.local.ClientEntity
import org.example.project.data.network.SupabaseClient
import org.example.project.domain.model.Client
import org.example.project.domain.repository.ClientRepository

class ClientRepositoryImpl(
    private val clientDao: ClientDao,
    private val remoteDb: Postgrest
) : ClientRepository {

    // 1. Relies on Local DB as Single Source of Truth
    override fun getClientsFlow(): Flow<List<Client>> {
        return clientDao.getAllClientsFlow().map { entities ->
            entities.map { Client(it.id, it.name, it.phoneNo, it.address) }
        }
    }

    // 2. Refresh local database cache from Remote Database (Supabase)
    override suspend fun refreshClientsCache() {
        val remoteClients = remoteDb["clients"].select().decodeList<ClientDto>()
        val entities = remoteClients.map { dto ->
            ClientEntity(dto.id, dto.name, dto.phoneNo, dto.address)
        }
        clientDao.insertClients(entities)
    }
}
```

## Core Constraints and Anti-Patterns
*   ❌ **Direct Thread Access:** Never block the main thread with SQL queries; always expose data streams via Kotlin `Flow` or specify asynchronous dispatcher environments.
*   ❌ **Leak Room Annotations:** Do not compile Room annotations or DB entities into the Domain module.
*   ❌ **Complex Types in DB:** Avoid storing nested objects directly; leverage `@TypeConverter` classes for complex mappings.
