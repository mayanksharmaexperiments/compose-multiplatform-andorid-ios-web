# Project Rules & Conventions (Compose Multiplatform)

This file serves as a global, always-on instruction manual for any AI Coding Assistant (e.g., Antigravity, Claude Code, Cursor) interacting with this project. It outlines our architectural conventions, coding guidelines, and development workflows.

---

## 1. Project Overview & Tech Stack
This is a **Compose Multiplatform (CMP)** and Kotlin Multiplatform (KMP) project targeting Android, iOS, JS, and WasmJS.

*   **Shared UI:** Jetpack Compose Multiplatform (`commonMain`)
*   **Dependency Injection:** Koin (`commonMain`)
*   **Networking:** Ktor Client (`commonMain`)
*   **Remote Database & Auth:** Supabase (`supabase-kt` Postgrest & GoTrue)
*   **Local Cache:** Room Multiplatform & Jetpack DataStore (`commonMain`)
*   **State & ViewModels:** `androidx.lifecycle.ViewModel` (`commonMain`)
*   **Navigation:** Navigation 3 (State-driven composable routing)

---

## 2. Core Coding Rules (Always Enforced)

### Architecture Boundaries:
1.  **Pure Domain:** The domain layer (`commonMain/kotlin/org/example/project/domain`) must be written in **pure Kotlin** and have zero dependencies on Ktor, Room, Supabase, Serialization, or platform frameworks.
2.  **No DTO Leakage:** Keep database tables, JSON DTOs, and serialization models strictly encapsulated in the Data layer. Always use extension mapper functions to transform DTOs into pure Domain entities before returning them to domain/view layers.
3.  **Dependency Inversion:** ViewModels and Use Cases must depend purely on repository *interfaces*, never on concrete repository implementations or databases.

### Jetpack Compose UI:
1.  **State Hoisting:** Build stateless composable layouts. Host the active UI state inside ViewModels and pass immutable values and callbacks to child composables.
2.  **Lifecycle Collection:** Never collect StateFlows in Compose using the basic `.collectAsState()`. You must **always** collect using `collectAsStateWithLifecycle()` to prevent background processing leaks.
3.  **Lazy List Performance:** Always specify unique, stable `key` configurations and the correct `contentType` inside `LazyColumn` and `LazyRow` items to optimize recomposition reuse.
4.  **Lambda Deferral:** Defer fast-changing states (offsets, scroll values, animations) by reading them inside modifier lambdas (e.g., `offset { ... }` or `drawBehind { ... }`) to bypass composition/layout phases.

### Security:
1.  **Secret Isolation:** Never commit raw API keys or passwords to version control. Use the autogenerated `Config` file derived from `local.properties` or environment variables.
2.  **Encrypted Local Cache:** Never store plain passwords or sensitive JWT session tokens in standard DataStore Preferences; utilize secure Keychain (iOS) and EncryptedSharedPreferences (Android) settings.

### Interaction & Debugging:
1.  **Mandatory Root Cause Analysis (RCA):** If the user shares any error, bug, or asks a question, you MUST analyze, identify, and clearly explain the root cause *before* proposing or implementing any solution.
